no relay — the page cannot reach the API

The API refuses browser calls — it answers the preflight with 403 and no Access-Control-Allow-Origin, so the browser blocks the request and you get Failed to fetch. A relay fixes that: it runs in your terminal, where CORS does not apply, and it holds the API key so the page never carries it.

  1. Get the relay. relay.py sits next to this page in the repo. Save it anywhere.
  2. Start it. In a terminal: 
    python3 relay.py
    It asks once for your TokenRouter key (the brain) and your Google AI API key (the vision model), then remembers the Google one in google.key beside the script so it never asks again. Either can come from the environment instead — $TOKENROUTER_API_KEY and $GOOGLE_API_KEY. Python 3.8+ is the only requirement, no packages to install.
  3. Copy what it prints. It generates a fresh relay token each start and prints both lines: 
    Relay address   http://127.0.0.1:8787
Relay token     kQ7f...
  4. Paste them above and hit Test relay. Green means you are done.

Want a token that survives restarts? Pass your own instead of the generated one:

python3 relay.py --token "$(python3 -c 'import secrets;print(secrets.token_urlsafe(24))')"

Simplest option of all: the relay serves this page too. Put index.html, style.css, app.js and relay.py in one folder, run the relay, and open http://127.0.0.1:8787. Same origin, so no cross-origin rules apply at all — though you still paste the token above.

If the address is http:// and this page is https://, the browser treats it as a public page reaching your private network. The relay sends the Access-Control-Allow-Private-Network header for exactly this, and Chrome and Firefox accept it — but Safari does not. On Safari, open the page from the relay instead.
